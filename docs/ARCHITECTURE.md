# Fantasy Rune Factory implementation map

This map describes the current repository, including uncommitted working-tree code. The project version is Unity **6000.5.2f1** (`ProjectSettings/ProjectVersion.txt`). Product direction in `AGENTS.md` and `docs/DESIGN_SUMMARY.md` is separate from implemented behavior.

## Where to start

| Area | Location and role |
| --- | --- |
| Runtime | [`Assets/_Project/Scripts/`](../Assets/_Project/Scripts/) contains the `FantasyShapez.Runtime` assembly, grouped by `Runes`, `Resources`, `Grid`, `Buildings`, `Logistics`, `Production`, `Objectives`, `UI`, and `Camera`. |
| Scene and authoring data | [`Prototype.unity`](../Assets/_Project/Scenes/Prototype.unity) wires the grid, camera, placement controller, resource nodes, transport coordinator, and Hub. [`Prefabs/`](../Assets/_Project/Prefabs/) contains placeable instances; [`ScriptableObjects/Objectives/`](../Assets/_Project/ScriptableObjects/Objectives/) contains objective assets. |
| Editor and tests | [`PrototypeBeltTransportSetup.cs`](../Assets/_Project/Editor/PrototypeBeltTransportSetup.cs) is an Editor setup entry point. [`Tests/EditMode/`](../Assets/_Project/Tests/EditMode/) contains the `FantasyShapez.EditModeTests` assembly. |

## Gameplay data and flow

| System | Main files | Responsibility and connections |
| --- | --- | --- |
| Rune value | [`RuneData.cs`](../Assets/_Project/Scripts/Runes/RuneData.cs), [`RuneTypes.cs`](../Assets/_Project/Scripts/Runes/RuneTypes.cs), [`GlyphData.cs`](../Assets/_Project/Scripts/Runes/GlyphData.cs), [`ElementZoneAssignment.cs`](../Assets/_Project/Scripts/Runes/ElementZoneAssignment.cs) | Serializable rune structure: base shape, central sigil, optional primary element, glyphs, and legacy element-zone assignments. `Copy` creates a separate value; `Equals` compares components structurally, including glyph/zone sets. |
| Transformations | [`RuneOperations.cs`](../Assets/_Project/Scripts/Runes/RuneOperations.cs) | Pure operations return transformed `RuneData` for sigil engraving, glyph engraving/rotation, primary-element assignment, or legacy zone assignment. Production processes call these after their configured duration. |
| Resource supply | [`RuneStoneResourceNode.cs`](../Assets/_Project/Scripts/Resources/RuneStoneResourceNode.cs), [`RuneStoneResource.cs`](../Assets/_Project/Scripts/Resources/RuneStoneResource.cs), [`RuneResourceMap.cs`](../Assets/_Project/Scripts/Resources/RuneResourceMap.cs), [`RuneExtractorProcess.cs`](../Assets/_Project/Scripts/Production/RuneExtractorProcess.cs), [`RuneExtractor.cs`](../Assets/_Project/Scripts/Production/RuneExtractor.cs) | The map indexes serialized and active scene nodes by grid cell. Extractor placement requires a node; its timed process calls `RuneStoneResource.Extract()` and holds output in [`RuneOutputBuffer.cs`](../Assets/_Project/Scripts/Production/RuneOutputBuffer.cs). The extractor exposes output to transport. |
| Grid and placement | [`Grid2D.cs`](../Assets/_Project/Scripts/Grid/Grid2D.cs), [`GridSystem.cs`](../Assets/_Project/Scripts/Grid/GridSystem.cs), [`BuildingPlacementController.cs`](../Assets/_Project/Scripts/Buildings/BuildingPlacementController.cs), [`GridOccupancy.cs`](../Assets/_Project/Scripts/Buildings/GridOccupancy.cs), [`BuildingPlacement.cs`](../Assets/_Project/Scripts/Buildings/BuildingPlacement.cs) | `GridSystem` converts world positions to cells. The controller owns occupancy, reserves the Hub footprint, checks each option's placement behavior, instantiates its prefab, and initializes it. `BuildingRotation` supplies orientation; drag helpers in the controller interpolate belt paths. Removal checks `IBuildingRemovalRule`. |
| Placement adapters | [`IBuildingPlacementBehavior.cs`](../Assets/_Project/Scripts/Buildings/IBuildingPlacementBehavior.cs), [`Production/`](../Assets/_Project/Scripts/Production/), [`BeltPlacementBehavior.cs`](../Assets/_Project/Scripts/Logistics/BeltPlacementBehavior.cs) | Type-specific behaviors validate placement and initialize the placed component with its cell, direction, resource or coordinator. [`BuildingPlacementOption.cs`](../Assets/_Project/Scripts/Buildings/BuildingPlacementOption.cs) pairs a definition with its behavior. |
| Belts and handoff | [`BeltCell.cs`](../Assets/_Project/Scripts/Logistics/BeltCell.cs), [`BeltTransportSystem.cs`](../Assets/_Project/Scripts/Logistics/BeltTransportSystem.cs), [`IRuneInputReceiver.cs`](../Assets/_Project/Scripts/Logistics/IRuneInputReceiver.cs), [`IRuneOutputSource.cs`](../Assets/_Project/Scripts/Logistics/IRuneOutputSource.cs), [`BeltTransportCoordinator.cs`](../Assets/_Project/Scripts/Logistics/BeltTransportCoordinator.cs) | `BeltCell` holds movement progress and a rune. The pure transport system advances sorted belts, decides transfers from a pre-transfer occupancy snapshot, hands ready items to belts/receivers, then pulls machine outputs. Direction and `AllowsConcurrentInput` gate receiver transfers. The coordinator owns the system and advances it in `LateUpdate`. |
| Machine processing | [`EngraverProcess.cs`](../Assets/_Project/Scripts/Production/EngraverProcess.cs), [`ElementInfuserProcess.cs`](../Assets/_Project/Scripts/Production/ElementInfuserProcess.cs), [`GlyphRotatorProcess.cs`](../Assets/_Project/Scripts/Production/GlyphRotatorProcess.cs) | Each accepts one rune from its configured direction, snapshots settings on acceptance, advances `Idle → Processing → WaitingForOutput`, and retains output until transport takes it. The matching MonoBehaviours initialize/register processes, apply configuration, advance time, and show state: [`Engraver.cs`](../Assets/_Project/Scripts/Production/Engraver.cs), [`ElementInfuser.cs`](../Assets/_Project/Scripts/Production/ElementInfuser.cs), [`GlyphRotator.cs`](../Assets/_Project/Scripts/Production/GlyphRotator.cs). |
| Runtime controls and copy | [`ObjectivePanel.cs`](../Assets/_Project/Scripts/UI/ObjectivePanel.cs), [`BuildingPlacementController.cs`](../Assets/_Project/Scripts/Buildings/BuildingPlacementController.cs) | Clicking a placed Engraver/Infuser opens the compact configuration panel. The controller's `C` path captures that machine's recipe and building rotation for subsequent placement; `Engraver`/`ElementInfuser` apply the recipe to a new prefab instance before process initialization. It does not copy a process or installed upgrade. |
| Hub and inventory | [`Hub.cs`](../Assets/_Project/Scripts/Objectives/Hub.cs), [`HubReceiver.cs`](../Assets/_Project/Scripts/Objectives/HubReceiver.cs), [`AccelerationRuneInventory.cs`](../Assets/_Project/Scripts/Objectives/AccelerationRuneInventory.cs) | `Hub` registers one receiver for configured incoming directions. Valid-side deliveries are consumed; matching acceleration runes enter its inventory, while objective evaluation separately classifies the delivered rune. The receiver permits concurrent same-step inputs. |
| Objectives | [`ObjectiveDefinitionAsset.cs`](../Assets/_Project/Scripts/Objectives/ObjectiveDefinitionAsset.cs), [`ObjectiveDefinition.cs`](../Assets/_Project/Scripts/Objectives/ObjectiveDefinition.cs), [`ObjectiveProgress.cs`](../Assets/_Project/Scripts/Objectives/ObjectiveProgress.cs) | Ordered ScriptableObject assets create runtime definitions in `Hub.Awake`. Progress matches delivered runes with `RuneData.Equals`, counts cumulative requirements, and evaluates sustained delivery rates over completed windows in `AdvanceTime`; all current requirements must complete before the next objective. The panel reads this runtime progress. |
| Socket upgrade | [`Engraver.cs`](../Assets/_Project/Scripts/Production/Engraver.cs), [`EngraverProcess.cs`](../Assets/_Project/Scripts/Production/EngraverProcess.cs), [`AccelerationRuneInventory.cs`](../Assets/_Project/Scripts/Objectives/AccelerationRuneInventory.cs), [`ObjectivePanel.cs`](../Assets/_Project/Scripts/UI/ObjectivePanel.cs) | The implemented socket is the Engraver's acceleration upgrade. The panel asks the Hub inventory to consume one rune, then the process marks its socket occupied and shortens its effective processing duration. The Engraver renders socket state. No general machine socket framework appears in these paths. |

## Rendering and prefab wiring

[`BuildingDefinition.cs`](../Assets/_Project/Scripts/Buildings/BuildingDefinition.cs) stores an instance prefab, optional visual prefab, footprint, and tint. [`BuildingVisualFactory.cs`](../Assets/_Project/Scripts/Buildings/BuildingVisualFactory.cs) instantiates the visual prefab when supplied, otherwise creates a placeholder sprite; [`BuildingPreview.cs`](../Assets/_Project/Scripts/Buildings/BuildingPreview.cs) uses the same factory and shows validity and directional ports. The current `Prototype.unity` placement definitions point to `RuneExtractor`, `Belt`, `Engraver`, and `ElementInfuser` instance prefabs, with no visual prefabs assigned. Those instance prefabs contain `PlacedBuilding` plus their machine/belt component. [`Belt.cs`](../Assets/_Project/Scripts/Logistics/Belt.cs), the production MonoBehaviours, and `Hub.cs` create additional runtime markers and state visuals. Rendering reads placement/process state; transport and transformations operate on rune data.
